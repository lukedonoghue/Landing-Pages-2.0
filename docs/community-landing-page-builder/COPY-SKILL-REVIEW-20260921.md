# Copy Skill Review

## Scope And Evidence

Reviewed the community fork's entrypoint, research brief, copy/structure guide, copy doctrine, structured writer/reviewer workflow, reference coverage, build contract and acceptance rules. Compared them with the current Clarentis JSON copy master and the older local conversion-copywriter instructions. Only the community skill instructions were changed; no customer page or Luke original file was rewritten.

Blue Mountain's live page could not be fetched through this environment: web fetch failed, curl reported DNS failure, and one isolated managed browser reported ERR_NAME_NOT_RESOLVED. The user confirms the page is reachable. This is a tool/access-path limitation, not evidence the website is down. The in-app automation connection separately failed on a missing native module. Analysis uses the bundled September 16 non-OCR capture, source 6aebe071e132, and is not a fresh live visual review. Live comparison remains pending.

Also inspected the live text of [Clean Slate](https://www.cleanslatelandsolutions.com/) and consulted [Unbounce's landing-page anatomy](https://unbounce.com/landing-page-articles/the-anatomy-of-a-landing-page/), [NN/g's user-centric language guidance](https://www.nngroup.com/articles/user-centric-language/) and [web-writing research](https://www.nngroup.com/articles/applying-writing-guidelines-web-pages/). These support clear benefits, concrete features as reasons to believe, meaningful headings and objective language. They do not prove that either reference converts well; the local Blue Mountain record explicitly says performance not validated.

## What Was Wrong

1. **The stronger writing guidance was not mandatory on the lightweight route.** The default writer step loaded copy-and-structure; the richer doctrine was reached through the structured copy workflow, principally routed for guarded Worker builds. Static builds could miss it. This is a real instruction-routing defect, but it does not prove the Clarentis run skipped the doctrine: that run had the structured path.
2. **The brief did not force a positioning choice.** It recorded an offer, mechanism, objection and trust anchor, but did not explicitly select a leading supported advantage over the buyer's alternatives. All the right ingredients could be listed without a persuasive priority.
3. **Coverage could be mistaken for persuasion.** A relevant hero and complete service list could appear acceptable while offering little reason to choose the provider. The existing editorial criterion for outcome/mechanism was too broad to expose that consistently.
4. **Copy-before-design was ordered but not clearly enforced.** Writing appeared before design in the workflow, yet the build contract did not say that layout must preserve the complete sales argument rather than fit copy into a short template.
5. **Benefit review was advice, not a concrete bounded operation.** The core guide had good principles and a final read-through, but lacked the specific draft/revision procedure requested here.

The Clarentis headline, "Keep the numbers under control. Keep your business moving.", offers an understandable but interchangeable outcome. The supporting fixed-fee scope is more specific, yet was not developed into the dominant reason-to-choose argument. Services, fees and onboarding provide useful information; together they still do not automatically establish differentiated value. References to what the business lists also survived despite the existing rule against researcher-like copy. That is an execution/review failure as well as an instruction weakness, not a missing-rule excuse.

## Reference Lessons Applied

The Blue Mountain capture connects a concrete customer problem and result to material choice, fitting, installation options and a tangible enquiry deliverable. It supplies customer experience early, then expands different purchase concerns before explaining the full process. The useful lesson is benefit plus explanation plus evidence, not more adjectives or more sections for their own sake. Its lifetime/12-year warranty wording is a caution, not a claim to copy.

Clean Slate connects the service to usable property and makes the delivery experience more tangible through an identified owner, planning, customer evidence and a process that extends beyond enquiry. These are plausible persuasive mechanisms, not measured causes of success.

## Changes Made

- All builds now load the copy doctrine, not only the structured workflow.
- The existing strategy brief selects a leading advantage and maps source facts to buyer consequences, benefits, proof and section roles.
- Complete copy must precede layout; design cannot silently remove the argument or qualifiers.
- The starting architecture explicitly accounts for benefits, why choose, genuine proof/testimonials, mechanism, scope, process, questions and the final offer. Evidence-based adaptation remains allowed.
- Two focused passes now revise the same draft: benefit/choice, then sceptical buyer/reference. They reuse the existing review rather than add more rounds or files.
- Existing structured review criteria now explicitly assess the lead advantage and distinguish provider value from a generic category benefit. No new schema fields or criterion IDs.
- Final rendered acceptance checks that positioning and proof survived implementation.

I did not import the older skill's requirement for numbers in every headline, universal question bans, fixed section counts, or exaggerated example outcomes. They can force false claims and conflict with the reference itself.
