## Deployment sequence (operator approval required)

Inventory live instances, old Sheets endpoints/copies and existing outbound destinations first. Record current Worker version and a recoverable encrypted backup/Time Travel checkpoint. Review and approve all migrations before applying them. Migration 0011 logs everyone out, invalidates unused reset links, narrows manager privileges and disables legacy token-based Sheets destinations: plan the handoff accordingly.

Use the existing guarded publisher and approval gates for code and migrations. For an already deployed Worker, upload the new `GOOGLE_SHEETS_SIGNING_SECRET` separately from a trusted terminal; a repeated code-only release is not a secret upload. Complete the standalone connector setup in `google-sheets.md`, reconcile old layouts/data, then enable. Verify public form capture, authenticated CRM access, source identity through the signed verifier, blocked fallback aliases, normalized admin paths, current-password confirmation, and explicitly authorized synthetic Sheets create/erase. Do not inject real customer details into QA fixtures. A code-only rollback does not undo migrations or downstream deletions; restore/rollback must preserve the new authentication and erasure invariants.

## Local secrets and AI isolation

The generated Claude/Codex policies deny secret files, common Cloudflare credential locations and policy-file editing, and mark scraped pages, reference content and lead text as untrusted data. Project instructions alone are not a security boundary. Use a host version that supports the generated policy schema and test a harmless synthetic denied-path read **through both direct file tools and shell/subprocess tools**. User/global/managed configuration can change the result; Codex legacy sandbox settings can override default-permission profiles. Refuse production agent access if a probe succeeds or the host ignores the policy. Do not weaken the policy to make publishing work: run credential-bearing publishing/recovery in a separate trusted operator terminal. Remove inherited provider secrets from the agent environment and use narrowly scoped publishing credentials.

Initial setup still requires a protected `.secrets/production.json` and a bootstrap handoff on the operator's machine. Exclude private paths from sync, shared workspaces, evidence and backups that are not encrypted; use mode 0700 directories and 0600 files. After confirmed handoff run `npm run admin -- rotate-password --remote --out /PRIVATE/OUTSIDE/PROJECT/crm-password.txt`, store the new password in a password manager, remove the handoff file and verify duplicate bootstrap/current-password copies are gone. Recovery journals retain the generated password only until the operation has been reconciled; interrupted recovery intentionally retains it to prevent lockout. Hashes, provider tokens and D1 access remain sensitive even after password cleanup.

Use `npm run backup:encrypted -- --out /PRIVATE/OUTSIDE/PROJECT/backup.sql.age --recipient age1PUBLIC_RECIPIENT` (see `--help`/source for explicit target options). Install `age` first; keep the private decryption key off the exporting machine, ideally offline or in a separate managed recovery system. The wrapper uses a private temporary SQL file while exporting, encrypts immediately, and removes temporary plaintext on completion/failure; this is not forensic secure erasure or protection against a compromised operator OS. Remote plaintext exports require an explicit exceptional flag. Default operational retention: remove encrypted routine exports after 30 days unless the client's documented recovery/retention obligations require otherwise; review backups and deletion records at handoff and monthly. The tool does not autonomously delete the user's existing backups. D1 Time Travel follows the actual account plan and is not a replacement for a tested recovery plan.

Enable MFA for Cloudflare and the client-owned Google automation account, review recovery methods, configure zone WAF rate limiting on POST /api/leads and consider Access on the dedicated CRM host. These provider settings and the Google sharing ACL cannot be changed by a GitHub code patch. Do not claim they were configured without inspecting the live provider accounts.
